# lsh

## Build System

This project uses a **Kbuild-like** recursive make system. It is a clean-room
implementation inspired by the public design ideas of Linux Kbuild (recursive
make, per-directory `built-in.a`, thin archives, `FORCE` + mtime-based
incrementality). It does **not** share code with, and is **not** derived from,
the Linux kernel's `scripts/Makefile.*`. Do not assume standard Makefile
semantics.

### Key files

- `Makefile` — top-level entry, defines `progs` and `obj-<prog>`
- `scripts/Makefile.build` — top-level build logic
- `scripts/Makefile.subdir_build` — per-subdirectory build logic
- `scripts/Makefile.rules` — compile/link/ar rules
- `scripts/Makefile.utils` — utility functions (`kecho`, etc.)

### How it works

- Subdirectories are built recursively via `$(MAKE) -C`.
- Each directory produces `built-in.a` as a **thin archive** (`ar rcSTP`).
- `%/built-in.a` nested references are **flattened** by thin archive, not
  truly nested. The inner `.a`'s members become direct members of the outer `.a`.
- `built-in.a` depends on `$(objs)` and is a **real file target** (not `.PHONY`).
- `FORCE` is used to ensure recursive descent; actual rebuild decisions use mtime.
- `obj-<prog>` entries ending in `/` are auto-converted to `dir/built-in.a`:
  - `obj-lsh := program/` → `program/built-in.a`
  - `obj-lsh += applets/built-in.a` → kept as-is (explicit form still works)
  - The conversion is `$(patsubst %/,%/built-in.a,$(obj-lsh))`.
- A subdirectory `Makefile` declares its contents via `objs += ...`:
  - `objs += pwd.o cd.o` for object files
  - `objs += lenv/built-in.a` for a nested archive (explicit form)
  - `objs += lenv/` for a nested archive (auto-converted form)

### Commands

- `make` — build everything (incremental)
- `make clean` — recursively remove `.o`, `.d`, `built-in.a`, `lsh`
- `make V=1` — verbose output (shows actual commands, disables
  `--no-print-directory`)

### Rules

- Do not change `$(AR) rcSTP` to plain `ar rcs`. Thin archives are required
  for nested `built-in.a` flattening. Plain archives would make inner symbols
  invisible to the linker.
- Do not remove `FORCE` from recursive `built-in.a` rules without understanding
  the parent/child mtime problem. Without `FORCE`, a change inside a subdirectory
  may not be noticed by the parent.
- When adding a new source file, add it to the relevant subdirectory `Makefile`
  via `objs +=`.
- When adding a new subdirectory, reference it as `dir/` in the parent's `objs`
  (or `obj-<prog>`), not as `dir/built-in.a`, unless you need the explicit form.
- `cleanobjs` must include both `.o` and `.d` for each object; `.d` files are
  generated by `-MMD -MP`.
- `clean` recurses into subdirectories referenced by `%/built-in.a` in
  `cleanobjs`. Do not manually delete a subdirectory's `built-in.a` from the
  parent if the subdirectory has its own `clean` rule.
- When touching header files, only objects whose `.d` includes that header
  should rebuild. Do not force full rebuilds.
- `-include $(patsubst %.o,%.d,$(filter %.o,$(objs)))` is required for header
  dependency tracking. The `filter %.o` excludes `.a` entries so they are not
  passed to `-include`.
- `make[x]` in output is **recursion depth** (`MAKELEVEL`), not a process
  index and not related to `-j`. Multiple `make[2]` lines can run in parallel.
- Do not copy code from Linux kernel `scripts/Makefile.build`,
  `Makefile.subdir_build`, `Makefile.rules`, or any GPL-2.0 Kbuild
  implementation.
- When suggesting changes, prefer original code that fits this project's
  existing structure over verbatim upstream Kbuild snippets.
- If you reference upstream Kbuild behavior, describe it abstractly (e.g.,
  "Kbuild uses `FORCE` + `if_changed` to balance recursive descent with
  incremental rebuilds"), do not paste its implementation.

### Boundaries

- Never edit `scripts/Makefile.*` without verifying `make` and `make clean`
  still work.
- Never commit build artifacts (`.o`, `.d`, `built-in.a`, `lsh`).
- Never assume `.PHONY` targets behave like regular make targets in this
  Kbuild-like context.
- Never assume `make[x]` reflects parallel job indices.
